# 积分系统分析文档

## 📊 当前积分模式概览

> **核心策略**：从"口碑推荐"转向"内容裂变"，通过流量驱动实现快速用户增长

### 一、积分获取方式（流量驱动型）

| 获取方式 | 积分数量 | 类型 | 说明 |
|---------|---------|------|------|
| **新用户注册** | **+100** | `initial` | 注册立得，消除用户对"收费/消耗"的心理防线 |
| **页面点击奖励** | +1/点击 | `page_view` | 用户创建的页面每获得1个点击，赠送1积分（24小时内同一IP仅计1次） |

**核心变化**：
- ✅ **注册红利大幅提升**：从 +3 提升至 +100，给足诚意
- ✅ **取消推荐码机制**：不再依赖"邀请好友"模式
- ✅ **流量变现**：让用户通过分享页面获取点击来赚取积分
- ✅ **内容裂变**：利用用户生成的内容作为流量入口

---

### 二、积分消耗方式

| 功能 | 消耗积分 | 订阅豁免 | 说明 |
|------|---------|---------|------|
| **AI 内容生成** | -10 | ✅ Pro | 每次生成内容（同步/异步） |
| **内容修复** | -10 | ✅ Pro | 每次修复内容 |
| **AI Guide 对话** | **-2** | ✅ Pro | 每次对话消耗2积分 |

**重要发现**：
- ✅ **AI Guide 每次对话消耗 2 积分**（已登录用户，非 Pro 订阅）
- ✅ 未登录用户有免费试用限制（1次对话）
- ✅ 所有积分消耗都有 Pro 订阅豁免
- ✅ **注册红利**：100积分足够用户使用50次 AI Guide 对话或10次内容生成，消除心理防线

### 三、流量驱动机制（核心策略）

#### 3.1 页面点击奖励系统

**奖励规则**：
- **单次点击奖励**：用户创建的页面，每获得1个点击，赠送1积分
- **防刷机制**：同一 IP/设备 24小时内多次点击仅计 1 次

**防刷机制详细说明**：
- 同一 IP/设备 24小时内多次点击仅计 1 次
- 内部埋点记录点击来源（Referer）
- 异常流量检测：如果某账号 90% 的点击来自同一地区或异常 UA，自动触发风险核查，暂停积分发放

**技术实施**：
- 点击统计：通过页面访问日志记录
- 实时积分发放：点击后立即发放积分
- 数据审计：关联 Google Analytics (GA4) 进行周度审计

**业务流程**：
```
1. 用户访问内容页面
   ↓
2. 记录访问日志（IP、UA、Referer、时间）
   ↓
3. 检查24小时内该IP是否已访问过该内容
   ↓
4. 如果是首次访问（24小时内）：
   - 标记 is_unique = true
   - 发放积分 +1 给内容创建者
   - 记录到 user_credits 表（change_type = 'page_view'）
   ↓
5. 如果不是首次访问：
   - 标记 is_unique = false
   - 不发放积分
```

#### 3.2 游客转化机制

**转化策略**：
- 游客在试用完免费次数后，弹窗提示："注册即领 100 积分，并保存刚才生成的精彩内容"
- 设置"看一半/克隆模版需注册"的逻辑，将流量转为用户
- 优化登录流程，确保护存数据合并顺畅，让游客转注册的流失率降到最低

**数据合并逻辑**：
- `content` 表：`visitor_id` → `created_by`
- `ai_usage_logs` 表：`visitor_id` → `user_id`
- `ai_conversations` 表：`visitor_id` → `user_id`
- 注册后立即发放 100 积分（`change_type = 'initial'`）

### 四、订阅豁免机制

#### 4.1 订阅计划

| 计划 | 积分豁免 | 说明 |
|------|---------|------|
| **Pro** | ✅ 完全豁免 | 所有功能免积分消耗 |
| **Lite** | ❌ 不豁免 | 需要消耗积分 |
| **无订阅** | ❌ 不豁免 | 需要消耗积分 |

#### 4.2 豁免检查逻辑

```javascript
// 检查订阅状态
const { data: subscription } = await DatabaseService.getActiveSubscription(userId);
if (subscription && subscription.plan === 'pro') {
  shouldConsume = false; // Pro 用户不消耗积分
}
```

**豁免范围**：
- ✅ AI 内容生成（-10积分）
- ✅ 内容修复（-10积分）
- ✅ AI Guide 对话（-2积分）

### 五、免费试用机制（未登录用户）

#### 5.1 试用限制

| 功能 | 免费次数 | 限制方式 |
|------|---------|---------|
| **内容生成** | 1次 | `visitor_usage.content_generated` |
| **AI Guide 对话** | 1次 | `visitor_usage.ai_guide_used` |

#### 5.2 试用状态管理

**表结构**：`visitor_usage`
- `visitor_id`: 游客ID（格式：`visitor-{uuid}`）
- `content_generated`: 是否已生成内容（布尔值）
- `ai_guide_used`: 是否已使用 AI Guide（布尔值）
- `expires_at`: 过期时间（当前为 `null`，不设置过期）

**试用逻辑**：
1. 首次使用功能时，检查对应标志位
2. 如果未使用，允许使用并标记为已使用
3. 如果已使用，提示登录后继续使用

#### 5.3 数据合并

注册后，游客数据会合并到用户账号：
- `content` 表：`visitor_id` → `created_by`
- `ai_usage_logs` 表：`visitor_id` → `user_id`
- `ai_conversations` 表：`visitor_id` → `user_id`（新表）

### 六、积分消耗流程

#### 6.1 AI 内容生成流程

```
1. 用户请求生成内容
   ↓
2. 检查订阅状态（Pro 用户豁免）
   ↓
3. 检查积分余额（非 Pro 用户，需要 10 积分）
   ↓
4. 执行 AI 生成
   ↓
5. 生成成功后扣除积分（-10）
```

**代码位置**：
- `edu/backend/src/api/ai.js` - `/api/ai/generate`（同步）
- `edu/backend/src/api/ai.js` - `/api/ai/generate-async`（异步）

#### 6.2 内容修复流程

```
1. 用户请求修复内容
   ↓
2. 检查订阅状态（Pro 用户豁免）
   ↓
3. 检查积分余额（非 Pro 用户，需要 10 积分）
   ↓
4. 执行 AI 修复
   ↓
5. 修复成功后扣除积分（-10）
```

**代码位置**：
- `edu/backend/src/api/content_fix.js` - `/api/content/fix`

#### 6.3 AI Guide 流程

```
1. 用户打开 AI Guide
   ↓
2. 未登录用户：检查免费试用状态
   ↓
3. 已登录用户：检查订阅状态和积分余额
   - Pro 订阅：豁免，直接使用
   - 非 Pro 订阅：需要 2 积分，余额不足则拒绝
   ↓
4. 执行对话（流式响应）
   ↓
5. 对话成功后扣除积分（-2，仅非 Pro 已登录用户）
```

**重要**：
- ✅ **已登录用户（非 Pro）**：每次对话消耗 2 积分
- ✅ **Pro 订阅用户**：完全豁免，不消耗积分
- ✅ **未登录用户**：有免费试用限制（1次对话），不消耗积分

### 七、积分数据库结构

#### 7.1 `user_credits` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `user_id` | UUID | 用户ID |
| `change_type` | TEXT | 变更类型：`initial`, `page_view`, `usage`, `admin` |
| `change_amount` | INTEGER | 变更数量（正数=增加，负数=减少） |
| `related_user_id` | UUID | 关联用户ID（推荐时使用，可为NULL） |
| `related_content_id` | UUID | 关联内容ID（页面点击时使用，可为NULL） |
| `created_at` | TIMESTAMPTZ | 创建时间 |

**积分余额计算**：
```sql
SELECT SUM(change_amount) FROM user_credits WHERE user_id = $1;
```

**变更类型说明**：
- `initial`: 新用户注册奖励（+100积分，待实现）
- `page_view`: 页面点击奖励（+1积分）
- `usage`: 功能使用消耗（负数：-10/-2）
- `admin`: 管理员手动调整

**新增字段建议**：
- `related_content_id`: 用于关联页面点击奖励的具体内容ID，便于防刷检测和审计

#### 7.2 `subscriptions` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `user_id` | UUID | 用户ID |
| `plan` | TEXT | 订阅计划：`pro`, `lite` |
| `status` | TEXT | 订阅状态：`active`, `canceled`, `past_due` |
| `current_period_end` | TIMESTAMPTZ | 当前周期结束时间 |

#### 7.3 页面点击统计表（需要新建）

**建议表结构**：`page_views` 或 `content_views`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 主键 |
| `content_id` | UUID | 内容ID（外键关联到 `content.id`） |
| `viewer_ip` | TEXT | 访问者IP |
| `viewer_user_agent` | TEXT | 访问者UA |
| `referer` | TEXT | 来源页面 |
| `created_at` | TIMESTAMPTZ | 访问时间 |
| `is_unique` | BOOLEAN | 是否计入积分（24小时内同一IP仅计1次） |
| `credits_awarded` | BOOLEAN | 是否已发放积分（避免重复发放） |

**索引**：
- `(content_id, created_at)` - 用于统计单页面点击
- `(viewer_ip, created_at)` - 用于防刷检测
- `(content_id, viewer_ip, created_at)` - 用于判断24小时内是否已计分

**业务逻辑**：
1. 记录每次页面访问（无论是否计入积分）
2. 判断是否在24小时内同一IP已访问过该内容
3. 如果是首次访问（24小时内），标记 `is_unique = true` 并发放积分
4. 如果已访问过，标记 `is_unique = false`，不发放积分

### 十、总结

**优化后的积分模式特点**：

1. ✅ **注册重赏**：100积分直接入账，给足诚意，消除用户心理防线
2. ✅ **流量变现**：让用户分享页面通过点击赚取积分，解决"推荐难"的问题
3. ✅ **内容裂变**：利用用户生成的内容作为流量入口，自然带动注册增长
4. ✅ **极简转化**：优化登录流程，确保护存数据合并顺畅，让游客转注册的流失率降到最低

**核心策略转变**：

| 维度 | 旧策略（推荐码） | 新策略（内容裂变） |
|------|----------------|------------------|
| **获客方式** | 邀请好友注册 | 分享内容页面 |
| **奖励机制** | 推荐成功+3积分 | 页面点击+1积分 |
| **注册红利** | +3积分 | **+100积分** |
| **传播动力** | 需要主动邀请 | 自然分享成果 |
| **转化门槛** | 需要输入推荐码 | 点击即转化 |

**增长漏斗模型**：

```
1. 生产爆款内容
   ↓
2. 外部曝光（知乎、小红书、微博）
   ↓
3. 点击引流（每点击送积分）
   ↓
4. 强制转化（看一半/克隆需注册）
   ↓
5. 注册即领100积分
   ↓
6. 用户继续生成和分享内容
   ↓
7. 形成内容裂变循环
```

**风控要点**：

1. **注册安全检查**：
   - 图形验证码或滑块验证
   - 限制同一IP每天注册上限

2. **流量质量审计**：
   - 记录点击来源（Referer）
   - 异常流量检测（90%点击来自同一地区/异常UA）
   - 自动触发风险核查，暂停积分发放

3. **数据对比**：
   - 自建工具记录实时积分发放
   - 关联 Google Analytics (GA4) 进行周度审计

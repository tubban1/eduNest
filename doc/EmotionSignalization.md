在本地（Layer 1）实现轻量级的情绪词识别，通常是指不依赖大型预训练模型（如 BERT 或 LLM），而是在预处理阶段通过**词典匹配+规则引擎**的方式快速筛选。

这种方法的核心优势是：**速度极快、内存占用低、逻辑透明且易于干预。**

以下是技术实现方案：

### 1. 核心组件：情绪词典 (Sentiment Lexicon)

这是“轻量级”方案的基石。你需要构建或引入现成的情绪词库（如大连理工大学情感词汇本体、HowNet 情感词典或 SentiWordNet）。

* **情感词表：** 包含词条及其极性得分（例如：高兴 +1.0，愤怒 -1.2）。
* **程度副词表：** 给不同程度的词赋予权重（例如：“非常” x2.0，“稍微” x0.5）。
* **否定词表：** 逻辑翻转词（例如：“不”、“没有”、“绝非”），遇到时分值乘以 -1。

### 2. N-gram 的作用：处理上下文偏移

单纯的单字匹配无法处理“不开心”这种情况。通过 N-gram（通常是 Bigram 或 Trigram），你可以捕获局部的语义关联。

* **实现逻辑：** 在分词后，扫描当前情绪词前后的 N 个词。
* **例子：** “我不觉得这件衣服漂亮。”
* Unigram 识别到“漂亮” (+1)。
* Bigram 识别到“不”+“漂亮” (利用否定词逻辑改为 -1)。



### 3. 算法实现步骤 (Scoring Logic)

技术路线上可以分为以下四个阶段：

#### A. 文本预处理与分词

使用轻量级分词工具（如 Python 的 **Jieba** 或 C++ 的 **CppJieba**）。

* **输入：** "这个产品真的非常不好用。"
* **分词结果：** `["这个", "产品", "真的", "非常", "不", "好用"]`

#### B. 序列匹配与权重叠加

遍历分词序列，定位情绪词，并向前回溯寻找修饰词（程度词、否定词）。

#### C. N-gram 窗口滑动

设置一个固定窗口（如 ）。当匹配到情感词  时，检查  之前的  个词。

1. **Count Negations:** 统计窗口内的否定词数量（奇数个则分值反转，偶数个通常维持原意）。
2. **Multiply Intensity:** 如果窗口内存在程度副词，将情感词的基础分乘以该权重。

#### D. 轻量级 Score 聚合

将整个句子的分值进行归一化，映射到 `[-1, 1]` 或 `[0, 100]` 区间。

### 4. 代码逻辑示例 (伪代码)

```python
# 简化版 Layer 1 逻辑
def get_sentiment_score(tokens):
    score = 0
    for i, word in enumerate(tokens):
        if word in sentiment_dict:
            base_score = sentiment_dict[word]
            
            # 检查前两个词 (Bigram/Trigram 逻辑)
            window = tokens[max(0, i-2) : i]
            
            # 处理程度副词
            multiplier = 1.0
            for w in window:
                if w in degree_dict:
                    multiplier *= degree_dict[w]
            
            # 处理否定词
            negation = 1
            for w in window:
                if w in negation_dict:
                    negation *= -1
            
            score += base_score * multiplier * negation
    return score

```

### 5. 为什么叫 Layer 1？

在工业界，这通常作为**前置过滤器**：

1. **初筛：** 快速判断文本是否有情绪色彩。如果没有（分值为 0），则不调用昂贵的 GPU 模型。
2. **特征提取：** 将这个轻量级 Score 作为一个特征向量，输入到后续的分类器中。
3. **实时监控：** 在边缘侧（手机端或单片机）直接运行，不需要联网。

**局限性提醒：**
这种方案无法识别**反讽**（例如：“你可真行啊！”）或**长距离依赖**的情绪表达。如果需要处理这类问题，才需要升级到基于 Transformer 的更高层模型。

对于你的技术栈（Node.js, TypeScript, Next.js, Vercel），实现 **Layer 1（轻量级过滤层）** 的建议是：**尽量选择轻量级、纯 JavaScript/TypeScript 的库**，以避免 Vercel Serverless Functions 的冷启动延迟（Cold Start）和环境兼容性问题。

以下是针对不同语言和需求的库推荐及安装建议：

### 1. 英文环境：推荐使用 `sentiment`

如果你处理的是英文文本，这个库是 Layer 1 的完美选择。它基于 AFINN 词典，计算极其快速，且没有任何外部重量级依赖。

* **安装：** `npm install sentiment`
* **优点：** 极轻，支持自定义权重。
* **缺点：** 仅限英文。

### 2. 中文环境：推荐方案

中文不能像英文那样简单地按空格分词，因此需要先进行“分词”（Tokenization）。

#### A. 分词库：`jieba-js` (推荐)

* **安装：** `npm install jieba-js`
* **注意：** 建议使用 `jieba-js`（纯 JS 版）而不是 `node-jieba`（包含 C++ 绑定）。在 Vercel 的 Serverless 环境中，带有 C++ 编译插件的库（Native Modules）经常会因为运行环境不一致导致部署失败。
* **作用：** 将“我今天很不开心”切分为 `["我", "今天", "很", "不开心"]`。

#### B. 情感得分：自定义精简字典

由于目前 Node.js 社区缺乏一个像 `sentiment` 那样完美适配中文的超轻量库，Layer 1 的最佳实践是**分词 + 字典查找**。
你可以下载常用的中文情感词典（如大连理工、NTUSD 或知网 Hownet），将其精简后存为 `.json` 文件。

### 3. 在 Vercel (Next.js) 中的实现代码 (TypeScript)

在你的 Next.js API Route 中，你可以这样写：

```typescript
// pages/api/analyze.ts 或 app/api/analyze/route.ts
import { SentimentAnalyzer } from 'some-logic'; // 伪代码

// 建议：直接在本地维护一个简单的 JSON 词典，避免安装大型库
const positiveWords = new Set(['好', '赞', '棒', '开心', '优秀']);
const negativeWords = new Set(['差', '烂', '恶心', '难过', '失望']);

export async function POST(req: Request) {
  const { text } = await req.json();
  
  // --- Layer 1: 极速计算 ---
  // 这里可以简单地用关键词包含来做初筛
  let score = 0;
  const words = text.split(''); // 中文简单实现，复杂点可以用 jieba-js
  
  words.forEach((word: string) => {
    if (positiveWords.has(word)) score += 1;
    if (negativeWords.has(word)) score -= 1;
  });

  // 如果 Layer 1 结果不确定（例如得分为 0），再触发 Gemini (Layer 2)
  if (Math.abs(score) < 1) {
    // 调用 Gemini API...
  }

  return Response.json({ score });
}

```

### 4. 关键避坑指南

1. **避开 C++ 模块**：不要安装 `node-jieba` 或 `canvas` 等需要本地编译的库，否则部署到 Vercel 时会报错。
2. **避免在 Edge Runtime 使用大库**：如果你在 Next.js 中使用 Edge Runtime，很多传统的 Node.js 库可能无法运行（因为缺乏 Node 核心 API 支持）。建议使用标准 Node.js Runtime 部署这些 API。
3. **词典文件位置**：将词典 `.json` 文件放在项目根目录或 `public` 文件夹中，确保打包时能被 Vercel 读取。

### 总结

* **英文**：安装 `sentiment`。
* **中文**：安装 `jieba-js` (分词) + 自研一个简单的 `.json` 权重表。
* **极致轻量**：如果只需要简单的“好/坏”判断，连库都不用装，直接用一个 `Set` 集合通过 `string.includes()` 做关键词匹配即可。


⏱ 延迟：**<1ms**

## 🔹 Layer B：轻量语义向量（核心）

**只在 Layer A 没命中或命中不确定时使用**

### 做什么？

* 把用户输入转成 embedding
* 与 **情绪原型句** 做相似度比较

### 情绪原型库（例）

```json
[
  { "label": "learning_frustration", "text": "我一直学不会，很沮丧" },
  { "label": "low_mood", "text": "最近什么都提不起劲" },
  { "label": "hopeless", "text": "感觉未来没什么意义" }

```

### 判断逻辑

```ts
sim = cosine(userEmbedding, prototypeEmbedding)

if sim > 0.85 → L2
if sim > 0.7 → L1
else → ignore
```

👉 这一层能捕捉：

* 隐晦表达
* 换词
* 口语 / 青少年语言

```ts
function lightSignalCheck(text, studentState) {
  // A. 快速关键词
  const keywordHit = keywordMatch(text)
  if (keywordHit.level === "L3") return { flag: true, level: "L3" }

  // B. 语义向量
  const semanticLevel = semanticMatch(text)
  
  // C. 状态升级
  const finalLevel = stateAdjust(semanticLevel, studentState)

  return {
    flag: finalLevel !== null,
    level: finalLevel,
    hint: semanticLevel
  }
}
```

## 一、一句话区分（先记住）

* ❌ **错误理解**：
  每条消息 → 调用一次完整 emotionAgent（高成本、过度监控）

* ✅ **正确设计**：
  每条消息 → 经过 **轻量情绪过滤 → 条件性升级**

---

## 二、推荐的三层触发机制（非常成熟）

### 🟢 Layer 0：轻量情绪过滤（Always-on，但极轻）

**每一条学生输入都会经过这一层**

但它不是“真正的 emotionAgent”，而是：

* 关键词 + embedding + 简单分类
* 本地 / 低成本模型
* 低延迟（<10ms）

#### 示例

```ts
lightSignal = emotionFilter.quickCheck(text)
```

输出类似：

```json
{
  "flag": false,
  "hint": "learning_frustration"
}
```

👉 **90% 的输入在这里就结束了**

---

### 🟡 Layer 1：emotionAgent（条件触发）

**只有在以下情况才激活 emotionAgent：**

* 出现负面情绪关键词
* 连续多轮挫败
* 学习行为异常（跳题、退出）
* 情绪状态连续下降

#### 伪代码

```ts
if (
  lightSignal.flag === true ||
  recentNegativeCount > threshold ||
  learningDropDetected
) {
  emotionAgent.analyze(fullContext)
}
```

👉 现实中，大约 **10–20% 的对话** 会触发这一层

---

### 🔴 Layer 2：强制安全升级（极少，但必须）

**只在明确高风险时触发**

* 自伤 / 自杀表达
* 极端绝望语句

```ts
if (emotionSignal.riskLevel === "L3") {
  safetyAgent.takeOver()
}
```

👉 <1% 的对话，但**100% 必须命中**

---

## 三、为什么“每次都激活 emotionAgent”是坏设计？

### 1️⃣ 成本爆炸（不只是钱）

* LLM 情绪分析 ≠ 免费
* 高并发下极其不划算

---

### 2️⃣ 法律与合规风险

在欧洲（你在瑞士 / 欧盟语境）：

> **持续心理分析 = 潜在敏感数据处理**

如果你：

* 每句话都做深度情绪分析
* 却没有明确必要性

👉 **可能违反 GDPR 的数据最小化原则**

---

### 3️⃣ 用户感知问题（非常真实）

学生会产生一种感觉：

> “我每说一句话，都被心理分析”

这在青少年场景是 **非常危险的体验**

---

## 四、正确的工程心智模型（请记住这个）

> **Emotion Agent 不是监听器**
> **它是一个安全气囊**

* 平时不用
* 出事必须弹
* 弹了必须负责

---

## 五、一个推荐的完整决策流程（工程版）

```
Student Input
   ↓
Light Emotion Filter (fast)
   ↓
Is there a signal?
   ├── No → Normal Teaching
   └── Yes
        ↓
   Emotion Agent (deep)
        ↓
   Risk Level?
   ├── L1 → Teaching Support
   ├── L2 → Gentle Escalation
   └── L3 → Safety Agent takeover
```
